## 1. 插件简介

**AI Agent 智能助手** 是 emlog 博客平台首款基于 **ReAct Agent + 工具调用 + 三层记忆系统** 的智能运维插件。它不仅仅是"聊天机器人"，而是一个能真正**读懂你的博客**、**操作你的博客**的 AI 助手。

### 核心能力

| 能力 | 说明 |
|------|------|
| 🤖 智能对话 | 基于大语言模型（LLM）的自然语言对话 |
| 📝 文章管理 | AI 帮你写文章、发布、修改、搜索 |
| 🖼️ AI 配图 | 自动生成文章配图并设为封面 |
| 🧠 三层记忆 | 短期会话缓存 + 长期用户记忆 + 站点上下文 |
| 🔧 工具调用 | 17 种内置工具，AI 可实际操作博客 |
| ⏰ 自动发文 | 定时自动生成并发布文章 |
| 🔒 安全防护 | 权限分级、危险操作拦截、频率限制 |
| 🎨 人格定制 | 通过 SOUL.md 自定义 AI 的角色和风格 |

### 技术架构

```
用户输入 → 前端对话窗口 → API 接口
  → PromptBuilder（组装系统提示词：人格 + 站点上下文 + 记忆）
  → LLM API（大语言模型推理）
  → AgentLoop（多轮工具调用循环）
  → ToolRunner（执行具体工具）
  → 返回结果给用户
```

## 3. 安装步骤

### 方式一：后台插件管理安装（推荐）

1. 登录 emlog 后台
2. 进入 **「插件」→「插件管理」**
3. 点击 **「安装插件」**，上传 `ai_agent` 插件压缩包
4. 安装完成后，在插件列表中找到 **「AI Agent 智能助手」**
5. 点击 **「启用」**
6. 点击 **「设置」** 进入配置页面

### 方式二：手动上传安装

1. 将 `ai_agent` 文件夹上传到 `content/plugins/` 目录下
2. 确保目录结构为：`content/plugins/ai_agent/ai_agent.php`
3. 登录 emlog 后台 → **「插件」→「插件管理」**
4. 找到 **「AI Agent 智能助手」**，点击 **「启用」**

### 安装后首次配置流程

```
启用插件 → 点击「设置」→ 「基础设置」Tab
  → 配置 LLM 接口（API 地址 + 密钥 + 模型）
  → 保存设置
  → 前台刷新页面，右下角出现 🤖 按钮
  → 点击按钮开始对话
```

#### 温度值

| 字段 | 说明 |
|------|------|
| **名称** | 温度值（Temperature） |
| **说明** | 控制 AI 回复的随机性。值越低回复越确定、越保守；值越高回复越随机、越有创意 |
| **范围** | 0 ~ 1，支持小数（步长 0.1） |
| **推荐值** | **0.7**（平衡创意与准确性） |
| **注意** | 写文章建议 0.7~0.9；技术问答建议 0.3~0.5；需要精确结果时用 0 |

| 字段 | 说明 |
|------|------|
| **名称** | 最大生成长度（Max Tokens） |
| **说明** | AI 单次回复的最大 Token 数量。Token 不等于汉字，1 个汉字约 1.5~2 个 Token |
| **范围** | 100 ~ 8000 |
| **推荐值** | **2000**（约 1000~1300 个汉字） |
| **注意** | 值越大消耗 API 额度越多；写长文建议调大到 4000~8000；日常对话 2000 足够 |

### 4.3 Agent 循环配置

Agent 循环是插件的核心机制——AI 在回复过程中可以**自动调用工具**（如发文、搜索），并根据工具返回结果继续推理，形成"思考→调用→观察→再思考"的循环。

#### 开启 Agent 多轮循环

| 字段 | 说明 |
|------|------|
| **名称** | 开启 Agent 多轮循环 |
| **说明** | 开启后 AI 可以在一次对话中多次调用工具，实现复杂任务（如"写文章并发布"）；关闭后 AI 只能单轮回复，无法调用工具 |
| **选项** | 开启 / 关闭（单轮模式） |
| **推荐值** | **开启** |
| **注意** | 关闭后所有工具调用功能将失效，AI 变成纯聊天机器人 |

#### 最大工具轮次

| 字段 | 说明 |
|------|------|
| **名称** | 最大工具轮次 |
| **说明** | 单次对话中 AI 最多可以连续调用几轮工具。例如"写文章→查分类→发布→配图"需要 3~4 轮 |
| **选项** | 1 轮 / 2 轮 / 3 轮 |
| **推荐值** | **3 轮** |
| **注意** | 轮次越多消耗 Token 越多；简单任务 1~2 轮够用；复杂任务（发文+配图）需要 3 轮 |

#### 失败重试次数

| 字段 | 说明 |
|------|------|
| **名称** | 失败重试次数 |
| **说明** | 当工具调用失败时，AI 自动重试的次数 |
| **选项** | 不重试 / 1 次 / 2 次 |
| **推荐值** | **1 次** |
| **注意** | 重试会额外消耗 Token；网络不稳定时建议设为 1~2 次 |

### 4.4 记忆系统配置

插件采用三层记忆架构：

```
第一层：会话缓存（短期）  → 当前对话上下文，关闭窗口即失效
第二层：用户记忆（中期）  → 每个用户的偏好和历史，持久保存
第三层：站点上下文（长期）→ 分类、标签、文章统计，实时生成
```

#### 长期记忆

| 字段 | 说明 |
|------|------|
| **名称** | 长期记忆 |
| **说明** | 开启后 AI 会记住每个用户的偏好、历史对话摘要等信息，并在后续对话中参考 |
| **选项** | 开启 / 关闭 |
| **推荐值** | **开启** |
| **注意** | 关闭后 AI 每次对话都是"失忆"状态；记忆文件保存在 `ai/memory/` 目录 |

#### 自动整理触发次数

| 字段 | 说明 |
|------|------|
| **名称** | 自动整理触发次数 |
| **说明** | 每累计 N 次对话后，自动触发记忆整理（清理过期会话缓存和过期记忆文件） |
| **范围** | 5 ~ 100 |
| **推荐值** | **10** |
| **注意** | 值越小整理越频繁（消耗少量性能）；值越大记忆文件可能积累过多 |

#### 记忆过期天数

| 字段 | 说明 |
|------|------|
| **名称** | 记忆过期天数 |
| **说明** | 超过此天数未更新的用户记忆文件会被自动清理 |
| **范围** | 7 ~ 365 天 |
| **推荐值** | **90 天**（3 个月） |
| **注意** | 活跃用户的记忆会持续更新，不会被清理；只有长期不活跃的用户记忆才会过期 |

#### 会话缓存时间（秒）

| 字段 | 说明 |
|------|------|
| **名称** | 会话缓存时间 |
| **说明** | 用户关闭对话窗口后，会话上下文保留的时间。超时后会话失效，下次对话从头开始 |
| **范围** | 300 ~ 86400 秒（5 分钟 ~ 24 小时） |
| **推荐值** | **1800 秒**（30 分钟） |
| **注意** | 值太小用户切换页面后对话就断了；值太大会话缓存文件占用磁盘 |

### 4.5 访客权限

控制哪些用户可以使用 AI 功能。

#### 访客使用 AI

| 字段 | 说明 |
|------|------|
| **名称** | 访客使用 AI |
| **说明** | 是否允许未登录的访客使用 AI 对话功能 |
| **选项** | 禁止（仅登录用户）/ 允许 |
| **推荐值** | **禁止**（安全性更高） |
| **注意** | 允许访客使用会增加 API 消耗；建议配合每日限制使用 |

#### 访客每日对话上限

| 字段 | 说明 |
|------|------|
| **名称** | 访客每日对话上限 |
| **说明** | 每个访客（按 IP 区分）每天最多可以发送多少条消息 |
| **范围** | 0 ~ 100（0 = 不限制） |
| **推荐值** | **5 条** |
| **注意** | 仅在"访客使用 AI"设为"允许"时生效；建议设置限制防止恶意刷消耗 |

#### 注册用户每日对话上限

| 字段 | 说明 |
|------|------|
| **名称** | 注册用户每日对话上限 |
| **说明** | 每个注册用户每天最多可以发送多少条消息 |
| **范围** | 0 ~ 500（0 = 不限制） |
| **推荐值** | **50 条** |
| **注意** | 按用户 UID 统计，每天 0 点重置 |

#### 管理员每日对话上限

| 字段 | 说明 |
|------|------|
| **名称** | 管理员每日对话上限 |
| **说明** | 管理员每天的对话上限 |
| **范围** | 0 ~ 9999（0 = 不限制） |
| **推荐值** | **0**（不限制） |
| **注意** | 管理员通常需要频繁操作，建议不限制 |

### 4.6 发文权限

控制哪些角色的用户可以通过 AI 发布文章。

#### 允许 AI 发文的角色

| 字段 | 说明 |
|------|------|
| **名称** | 允许 AI 发文的角色 |
| **说明** | 勾选的角色可以通过 AI 指令发布文章 |
| **选项** | 管理员 / 编辑 / 作者 / 注册用户（无角色） |
| **推荐值** | 仅勾选 **管理员** |
| **注意** | ⚠️ 允许非管理员发文存在安全风险；建议至少配合"默认存草稿"使用 |

**各角色说明**：

| 角色 | emlog 角色标识 | 说明 |
|------|--------------|------|
| 管理员 | admin | 拥有全部权限 |
| 编辑 | editor | 可编辑他人文章 |
| 作者 | writer | 可发布自己的文章 |

#### AI 发文默认存草稿

| 字段 | 说明 |
|------|------|
| **名称** | AI 发文默认存草稿 |
| **说明** | AI 发布的文章默认保存为草稿还是直接发布 |
| **选项** | 是（推荐，需审核）/ 否（直接发布） |
| **推荐值** | **是（需审核）** |
| **注意** | ⚠️ 设为"否"时 AI 发布的文章会直接出现在前台，建议人工审核后再发布 |

### 4.7 安全防护

#### 高危操作拦截

| 字段 | 说明 |
|------|------|
| **名称** | 高危操作拦截 |
| **说明** | 开启后会拦截批量删除文章、清空站点数据等危险操作 |
| **选项** | 开启 / 关闭 |

| **注意** | ⚠️ 关闭此选项等于允许 AI 执行任何操作，包括删除文章，请谨慎 |

#### 用户单次输入长度限制

| 字段 | 说明 |

## 5. AI 人格设置

## 8. 自动发文

进入 **「自动发文」** Tab，配置 AI 定时自动生成并发布文章。

### 8.1 工作原理

自动发文采用**伪 Cron 触发**机制：

```
访客访问前台页面 → 1/10 概率触发 → 检查是否满足发文条件
→ 满足条件 → AI 自动生成文章 → 发布（或存草稿）
```

> ⚠️ **注意**：自动发文依赖访客访问触发，如果站点流量极低，发文可能不及时。建议配合服务器 Cron 任务使用（见附录）。

### 8.2 状态看板

| 指标 | 说明 |
|------|------|
| 上次运行 | 最近一次触发自动发文的时间 |
| 下次运行 | 预计下次触发的时间 |
| 累计运行 | 总共触发了多少次 |
| 上次成功 | 最近一次成功发文的时间 |

### 8.3 基础配置

| 字段 | 说明 |
|------|------|

| **选项** | 关闭 / 开启 |
| **推荐值** | **关闭**（按需开启） |
| **注意** | 开启后会消耗 API 额度，请确保账户余额充足 |

#### 发布间隔（分钟）

| 字段 | 说明 |
|------|------|
| **名称** | 发布间隔 |
| **说明** | 两次自动发文之间的最小间隔 |
| **范围** | 10 ~ 1440 分钟 |
| **推荐值** | **60 分钟**（每小时最多一篇） |
| **注意** | 间隔太短会快速消耗 API 额度；建议至少 30 分钟以上 |

| **注意** | 深夜发文阅读量通常较低 |

### 8.5 发文模式

#### 智能模式

- AI 自动分析站点的分类、标签和近期文章

## 13. 使用技巧

### 13.1 优化 AI 回复质量

1. **明确指令**：说清楚"写什么、发到哪个分类、用什么标签"，比"帮我写篇文章"效果好得多
2. **指定风格**：在 SOUL.md 中定义清楚写作风格，AI 会始终遵循
3. **善用记忆**：告诉 AI "记住我的偏好"，它会在后续对话中参考

### 13.2 节省 API 消耗

1. **关闭不需要的用户群体**：只允许管理员使用
2. **设置合理的每日限制**：防止意外消耗
3. **选择性价比高的模型**：DeepSeek V4 Pro 性价比最优
4. **控制最大生成长度**：日常对话设 2000，写长文时临时调大

### 13.3 提高发文效率

1. **批量操作**：一次指令让 AI 写多篇文章
2. **善用自定义 Prompt**：在自动发文中用 Prompt 控制内容方向
3. **配合标签和分类**：提前建好分类体系，AI 发文时直接指定

### 13.4 安全建议

1. **默认存草稿**：AI 发文先存草稿，人工审核后再发布
2. **限制非管理员权限**：发文权限只给管理员
3. **开启高危操作拦截**：防止误操作
4. **定期检查日志**：在执行日志 Tab 查看工具调用情况

### 13.5 记忆维护

1. **定期清理过期记忆**：在记忆管理 Tab 点击"清理过期记忆"
2. **检查记忆内容**：定期查看 AI 记住了什么，清除不需要的内容
3. **手动编辑记忆文件**：可以直接编辑 `ai/memory/` 下的 `.MEMORY.md` 文件

## 14. 常见问题 FAQ

### Q1: 前台看不到 🤖 按钮

**可能原因**：
1. 插件未启用 → 后台检查插件状态
2. 访客权限关闭且未登录 → 登录后刷新
3. 主题未调用 `index_footer` 钩子 → 检查主题的 footer.php
4. 浏览器缓存 → 强制刷新（Ctrl+F5）

### Q2: AI 不回复 / 回复超时

**可能原因**：
1. API 密钥错误 → 后台检查密钥配置
2. API 接口地址错误 → 确认地址以 `/chat/completions` 结尾
3. API 余额不足 → 登录服务商后台检查余额
4. 网络问题 → 服务器能否访问 API 地址
5. 超时时间太短 → 调大 API 超时时间和前端超时时间

### Q3: AI 不调用工具 / 不发文

**可能原因**：
1. Agent 循环未开启 → 基础设置中开启
2. SOUL.md 中规则被修改 → 重置为默认人格
3. 工具被禁用 → 高级设置中检查"禁用工具列表"
4. 权限不足 → 检查"仅管理员可用工具"配置

### Q4: 配图失败

**可能原因**：
1. 未配置配图 API → 填写绘图接口地址和密钥
2. 配图 API 余额不足 → 检查图像生成服务的余额
3. 配图目录不可写 → 检查 `content/upload/ai_images/` 权限
4. 模型名称错误 → 确认模型名称与服务商一致

### Q5: 自动发文不触发

**可能原因**：
1. 未开启自动发文 → 自动发文 Tab 开启
2. 站点没有访客访问 → 需要前台页面访问才会触发（1/10 概率）
3. 已达到每日上限 → 检查每日最大发文数
4. 不在发布时间段内 → 检查时间段设置
5. 发布间隔未到 → 检查间隔设置

**解决方案**：手动点击执行日志 Tab 的「运行定时任务」按钮测试。

### Q6: 消耗 Token 太多

**优化方案**：
1. 减少"会话历史传入条数"（如从 20 降到 10）
2. 减少"最大生成长度"（如从 2000 降到 1500）
3. 使用更便宜的模型（如 DeepSeek V4 Pro 而非 GPT-4o）
4. 关闭不需要的用户群体
5. 设置每日对话上限

### Q7: 如何迁移配置到新服务器

1. 旧服务器：后台导出设置 → 下载 JSON 文件
2. 复制 `ai/` 目录下的 SOUL.md、tools.json、memory/ 文件夹
3. 新服务器：安装插件 → 导入设置 JSON
4. 恢复 `ai/` 目录文件

### Q8: 记忆文件在哪里

记忆文件保存在：`content/plugins/ai_agent/ai/memory/`

- 每个用户一个文件：`{UID}.MEMORY.md`
- 访客记忆：`0.MEMORY.md`
- 格式：纯文本 Markdown，可直接编辑

### Q9: 如何备份和恢复

**备份内容**：
1. 插件配置（通过导出设置获取 JSON）
2. SOUL.md（AI 人格配置）
3. ai/memory/ 目录（用户记忆）
4. tools.json（如有自定义修改）

**恢复顺序**：
1. 安装插件 → 导入配置 JSON
2. 恢复 SOUL.md 和 memory/ 目录
3. 重启插件

### Q10: 配图返回\响应解析失败
**可能原因**：
1. PHP 未安装 fileinfo 扩展 → 配图下载后无法验证 MIME 类型
2. 解决方案：安装 fileinfo 扩展（宝塔面板 → PHP设置 → 安装扩展 → fileinfo）
3. 或升级插件到 v1.0.5+（已自动兼容 fileinfo 缺失情况）

### Q11: 配图请求返回 502 Bad Gateway

**可能原因**：
1. PHP-FPM 的 request_terminate_timeout 太短（默认100秒）
2. 配图涉及多次API调用，总耗时可能超过100秒
3. 解决方案：修改 PHP-FPM 配置，将 request_terminate_timeout 设为 300 秒
4. 宝塔面板 → PHP设置 → 配置修改 → request_terminate_timeout = 300

### Q12: 支持哪些 LLM 服务商

所有兼容 **OpenAI Chat Completions API** 协议的服务商都支持，包括但不限于：

- DeepSeek
- 阿里云通义千问（DashScope）
- 智谱 GLM
- 月之暗面 Moonshot
- 阶跃星辰 Step
- 小米 MiMo
- 硅基流动 SiliconFlow
- OpenAI
- 任何提供 OpenAI 兼容 API 的服务商

### Q13: AI 不调用工具 / 只回复文本不执行操作

**症状**：让 AI 发文、配图、搜索等操作时，AI 只返回文字描述而不实际调用工具。例如让 AI 配图，它回复「配图生成失败」但实际上从未调用 generate_image 工具。

**根因**：对话历史过长导致模型退化。当对话积累较多轮次后，AI 模型会从历史中学习到「只回复文本」的模式，逐渐不再调用工具。

**验证方法**：查看数据库中该对话的 tool_calls 字段是否为空 `[]`：
```sql
SELECT id, tool_calls, created_at FROM emlog_ai_agent_chat ORDER BY id DESC LIMIT 5;
```
如果 tool_calls 都是 `[]`，说明模型确实在跳过工具调用。

**解决方案**：
1. 点击对话窗口右上角的 **「+」** 按钮新建会话
2. 在新会话中重新发送指令
3. 如果仍然不调用工具，清空该用户的对话历史

**预防措施**：
- 建议将 **「会话历史传入条数」** 设置为 **10** 以下（基础设置 → Agent 配置）
- 定期新建会话，避免单次对话过长
- 如果频繁出现此问题，可考虑更换更强的模型（如 DeepSeek V4 Pro）

**原理说明**：LLM 模型在长上下文中倾向于模仿历史回复格式。如果历史中有多轮「纯文本回复」，模型会认为这是期望的行为模式，从而跳过工具调用。新建会话可清空历史上下文，让模型重新按系统提示词行事。

### Q14: AI 生成的链接域名错误

**症状**：AI 返回的文章链接指向错误的域名（如 `www.djzy.cc` 而非 `emlog.djzy.cc`）。

**根因**：AI 模型自行拼接了链接，而非使用工具返回的 `url` 字段。

**解决方案**：升级插件到 v1.0.5+（已修复此问题）。旧版本中：
- `get_article` 工具不返回 `url` 字段，AI 只能自己拼链接
- 新版本中工具自动返回正确的文章 URL，AI 直接使用即可

**如仍出现此问题**：检查 `ai/SOUL.md` 中是否包含以下规则：
```
文章链接必须使用工具返回的 url 字段，禁止自行拼接域名和路径
```

### 附录 C：服务器 Cron 配置

自动发文默认通过访客访问触发（1/10 概率），如果站点流量低，建议配置服务器 Cron 确保定时执行。

#### 方式一：Cron 访问触发 URL

在服务器的 crontab 中添加：

```bash
# 每 30 分钟触发一次自动发文检查
*/30 * * * * curl -s -o /dev/null "https://你的域名/?ai_agent_cron=1" > /dev/null 2>&1
```

#### 方式二：Cron 执行 PHP 脚本

```bash
# 每小时执行一次
0 * * * * cd /www/wwwroot/你的站点目录 && php content/plugins/ai_agent/cron.php >> /tmp/ai_agent_cron.log 2>&1
```

#### 配置步骤

1. SSH 登录服务器
2. 执行 `crontab -e` 编辑定时任务
3. 添加上述任一命令
4. 保存退出
5. 执行 `crontab -l` 确认任务已添加

> 💡 **建议**：配合自动发文的"发布时间段"设置，Cron 可以设为全天每 30 分钟执行一次，由插件自身控制实际是否在时间段内。
