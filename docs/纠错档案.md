### ERR-034：PromptBuilder convertParamsToArray 内存溢出
| 项目 | 内容 |
|------|------|
| 发现时间 | 2026-07-25 |
| 严重级别 | **高** |

**经验教训**：`json_decode()` 不带 `true` 返回 stdClass，`json_encode()` 对 stdClass 空对象序列化为 `{}`。无需额外转换。

**状态**：✅ 已修复

### ERR-038：callback_init 依赖未加载导致插件无法重新启用
| 项目 | 内容 |
|------|------|
| 发现时间 | 2026-07-25 |
| 严重级别 | **高** |
| 影响范围 | 所有新安装站点、插件禁用后重新启用 |

**问题描述**：emlog 核心 `Plugin_Model::activePlugin()` 启用插件时只加载 `callback.php` 文件，不加载主文件 `plugin.php`。但 `callback_init()` 调用了 `ai_agent_get_config()`（定义在 `ai_agent.php`）和 `new AIAgent_ChatHistory()`（定义在 `agent/ChatHistory.php`），导致 PHP Fatal Error。前端 AJAX 收到 HTML 错误而非 JSON，显示红圈叉号。

**根因分析**：
1. emlog `activePlugin()` 流程：只 `require_once callback.php` → 调用 `callback_init()`
2. `ai_agent_callback.php` 未加载主文件 `ai_agent.php`（ERR-037 时注释掉了 ChatHistory.php 的 require）
3. `callback_init()` 依赖的函数和类均未定义 → Fatal Error

**解决方案**：在 `ai_agent_callback.php` 顶部添加 `require_once __DIR__ . '/ai_agent.php';`，确保所有依赖在 `callback_init()` 执行前已加载。

**经验教训**：
- emlog 插件的 callback 文件必须自包含所有依赖，不能假设主文件已加载
- `require_once` 可安全重复加载（不会重复定义）
- callback 文件中引用的任何函数/类都必须在 callback 文件内自行加载

**状态**：✅ 已修复

### ERR-040：后台设置保存不生效（表单 action 路由错误）
| 项目 | 内容 |
|------|------|
| 发现时间 | 2026-07-25 |
| 严重级别 | **高** |
| 影响范围 | 所有设置保存（基础设置、AI人格、高级设置） |

**问题描述**：后台设置页三个表单的 `action` URL 错误：
- `ai_agent_basic_form` → `action=save_basic`
- `ai_agent_soul_form` → `action=save_soul`
- `ai_agent_advanced_form` → `action=save_advanced`

emlog 后台 `plugin.php` 只处理 `action=setting` 和 `action=save_setting`，其他 action 被静默忽略。AJAX 收到空响应，`submitForm()` 的 success 回调仍显示"保存成功"，造成保存成功的假象。

**解决方案**：三个表单全部改为 `action=save_setting`，并添加隐藏字段 `<input type="hidden" name="ai_agent_action" value="save_basic/save_soul/save_advanced">`，与已有的 `autopub_form` 保持一致。

**经验教训**：
- emlog 插件设置页的表单必须提交到 `action=setting` 或 `action=save_setting`
- 通过 `ai_agent_action` 隐藏字段区分具体操作
- AJAX 的 success 回调应校验响应内容，不能仅依赖 HTTP 状态码

**状态**：✅ 已修复

## 已知限制

### LIMIT-001：伪Cron 触发概率
自动发文采用"伪Cron"机制，约 10% 的访客访问会触发检查。低流量站点可能长时间不触发。

### LIMIT-002：图片压缩依赖 GD 库
`compressImage()` 检查 `imagecreatefromstring` 是否存在。GD 库不可用时跳过压缩。

### ERR-044: search_articles SQL查询含注释文本导致查询异常

| 项目 | 内容 |
|------|------|
| 发现时间 | 2026-07-26 |

**问题描述**：`tool_search_articles()` 的SQL查询字符串中，`// M-007: wildcards already escaped above` 注释文本被包含在PHP双引号字符串内部，成为SQL语句的一部分。实际发送到MySQL的SQL包含该注释文本，导致查询语法错误或返回异常结果。

**经验教训**：

- SQL字符串内不应包含任何非SQL内容
- 修改SQL后应打印实际执行的SQL进行验证

**状态**：✅ 已修复
